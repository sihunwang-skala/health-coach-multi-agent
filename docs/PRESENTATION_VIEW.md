# 제2형 당뇨병 고령자를 위한 식단·운동 코칭 Multi-Agent

SKALA 4기 광주 3반 · G088 · 왕시훈
[GitHub 저장소](https://github.com/sihunwang-skala/health-coach-multi-agent)

> 공개 논문과 자체 DB의 개인 건강정보를 함께 활용해 개인 맞춤형 식단·운동 답변을 제공하고, Safety Guard와 운영자 모니터링으로 예외 상황까지 처리하는 서비스입니다.

진단·처방이 필요한 요청에는 Safety Guard를 적용해 AI가 임의로 판단하지 않도록 하고, 약 변경은 의료진에게, 응급 증상은 119로 안내합니다.

---

## 1. 왜 필요한가

- 국내 **65세 이상 성인의 당뇨병 유병률은 29.3%**입니다.
- 당뇨 자기관리 교육 참여율은 병원·의원 **23.2%**, 보건소 **5.3%**에 그칩니다.
- 고령, 인슐린·설포닐우레아 사용은 저혈당 위험을 높이고, 신장병·망막병증 같은 질환에 따라 안전한 식단과 운동이 달라집니다.

### Standard RAG와 이 서비스의 차이

**Standard RAG**는 질문과 관련된 논문 근거를 찾아 답변하는 데 그칩니다.

**개발한 서비스**는 자체 DB에 저장된 사용자의 질환·복용 약·생활 습관·건강 기록을 질문과 결합해 개인별 답변을 제공합니다. 또한 응급 상황, 약 변경, 상담 연결, 기록 삭제처럼 논문 검색만으로 처리할 수 없는 요청도 하나의 서비스 안에서 처리합니다.

---

## 2. 추가한 기능

1. **논문 근거 답변**: 식단과 운동 질문에 출처 논문을 함께 제시합니다.
2. **개인 맞춤 답변**: 자체 DB의 개인 건강정보와 질문을 결합합니다.
3. **안전·서비스 처리**: 응급 상황과 임의 약 변경을 막고, 기록 저장·삭제와 상담 연결을 처리합니다.
4. **사용자·운영자 화면**: 사용자는 질문하고 응급 신호를 즉시 감지받으며, 운영자는 알림과 사용자별 기록·추세를 확인합니다.

### 사용한 핵심 기술과 사용 이유

| 기술 | 이 프로젝트에서 사용한 이유 |
|---|---|
| Multi-Agent · LangGraph | 필요한 Agent만 선택하고, 식단·운동 혼합 질문을 병렬 처리하며, 안전 검사를 별도 단계로 분리 |
| Agentic RAG | 질문을 여러 검색어로 나누고, 논문 근거를 다시 선택·검증해 개인 조건에 필요한 내용을 검색 |
| MCP | 논문 검색과 사용자 DB 기능을 Agent 코드에서 분리하고, 표준 tool interface로 호출 |
| Dependency Injection | 실제 OpenAI·MCP를 FakeLLM·in-memory MCP로 교체해 API 비용 없이 테스트 |
| FastAPI · SSE | 사용자·운영자 화면을 제공하고 처리 단계를 실시간 표시 |

## 3. Before / After 결과

평가 질문은 크게 두 종류입니다.

- **논문 근거가 필요한 건강 질문 60개**: 등록된 개인 건강정보를 반영하는 질문 30개 + 개인화하지 않는 일반 질문 30개
- **논문 검색이 필요 없는 서비스 메시지 40개**: 내 정보·기록, 잡담, 응급·약 변경, 상담 연결·개인정보 요청

같은 질문으로 다음 4가지 시스템을 비교했습니다.

1. Standard Paper-Search RAG
2. Health Agentic RAG
3. Single-Agent + Health Agentic RAG
4. **Multi-Agent + Health Agentic RAG (최종 시스템)**

| 지표 | Standard Paper-Search RAG | 최종 Multi-Agent | 변화 |
|---|---:|---:|---:|
| 건강 질문 답변 점수 | 75.3% | **91.5%** | **+16.2%p** |
| 필요한 논문 근거를 찾은 비율 | 31.6% | **60.2%** | **+28.6%p** |
| 안전 문제가 있는 답변 | 8.3% | **0%** | **−8.3%p** |
| 건강 질문 외 메시지 처리율 | 57.5% | **97.5%** | **+40.0%p** |
| 건강 질문 1개당 평균 응답 시간 | **4.1초** | 18.2초 | **14.1초 더 걸림** |

> 수치는 `eval/results/summary.json`에 저장된 2026-10-22 12:02의 마지막 100문항 전체 평가 결과입니다. 이후 추가한 한국어 번역·한 줄 요약 기능은 아직 전체 평가에 포함되지 않았습니다.

## 5. Trade-off와 추가 개선

### 얻은 것과 잃은 것

- 답변 점수는 **75.3% → 91.5%**, 논문 근거 검색은 **31.6% → 60.2%**로 향상했습니다.
- 여러 검색어 생성과 근거 선택이 추가되면서 평균 응답 시간은 **4.1초 → 18.2초**, 건강 질문 비용은 **$0.0002 → $0.0032**로 증가했습니다.
- 안전 검사로 위험 답변은 **8.3% → 0%**가 됐지만, code rule이 올바른 경고 문장을 위험하다고 판단하는 오탐이 있었습니다. 원인을 수정한 뒤 영향받은 답변 5개에서는 같은 문제가 다시 발생하지 않았습니다.

### 다음 개선

1. 독립적인 Query Transformation 병렬화, query·evidence cache, Evidence Selection 입력 축소
2. 한국어 번역을 포함한 100문항 품질·시간·비용 재평가 및 한국어 화면·영상 갱신
3. code rule과 작은 classification model을 결합해 안전 검사 오탐 축소
4. 반복 평가의 평균·신뢰구간과 holdout 질문, 의료진 표본 검토 추가

> 최종 시스템은 Standard RAG보다 답변 품질과 안전성이 높았습니다. 다음 목표는 이 성능을 유지하면서 더 빠르고 안정적인 서비스로 만드는 것입니다.
